# Part 4f - Necessary Modifications

## Necessary modifications to create our OData Service & Preview

#### Disabling draft support in the Behavior Projection
Unfortunately we recognized a problem with draft support in SAP's BTP environment: We're all using the same active travel database. But previously, we defined individual draft tables for every student. This ends up in problems and would basically prevent the Fiori application from working entirely. Therefore, we'll have to do some adjustments before continuing with publishing the business service in part 5.

>**TODO**  Please remove all draft enablements in your Behavior Projection `ZRAPH_##_C_TravelWDTP`. The final behavior projection should the look like this solution:


```abap
projection;

define behavior for ZRAPH_##_C_TravelWDTP alias Travel
use etag
{
  use create;
  use update;
  use delete;

  use action acceptTravel;

  use association _Booking { create; }
  use association _RoomReservation { create; }
}

define behavior for ZRAPH_##_C_BookingWDTP alias Booking
use etag
{
  use update;
  use delete;

  use association _Travel { }
  use association _BookingSupplement { create; }
}

define behavior for ZRAPH_##_C_BookingSupplWDTP alias BookingSupplement
use etag
{
  use update;
  use delete;

  use association _Travel { }
}

define behavior for ZRAPH_##_C_RoomReservationWDTP alias RoomReservation
use etag
{
  use update;
  use delete;

  use association _Travel { }
}
```
