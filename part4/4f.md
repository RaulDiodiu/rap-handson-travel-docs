# Part 4f - Necessary Modifications

## Necessary modifications to create our OData Service & Preview

### Disabling draft support in the Behavior Projection
Unfortunately we recognized a problem with draft support in SAP's BTP environment: We're all using the **same active travel database**. But previously, we defined **individual draft tables** for every student.  
This ends up in problems and would basically prevent the Fiori application from working entirely. Therefore, we'll have to do some adjustments before continuing with publishing the business service in part 5.

>**TODO**  Please remove **all** mentions of draft in your Behavior Projection `ZRAPH_##_C_TravelWDTP` and activate it again. I.e. delete all occurances of `use draft;` and `with draft;`. The final behavior projection should then look like this solution:

```abap
projection;

{
  use create;
  use update;
  use delete;
```

### Enabling the action acceptTravel for Service Consumption

Finally, we have to add two more annotations to our consumption CDS view in order to enable the `acceptTravel` action for the Fiori app. Otherwise, the actions wouldn't be shown in our Fiori app and would be useless.  
To do this, please open your Metadata Extension with the `@Metadata.layer: #CUSTOMER` - this is the fifth one which includes only the single field TravelID and is overwriting the MDE with `@Metadata.layer: #CORE`. It should be named something like `ZRAPH_##_C_TravelWDTP_CUSTOMER`.

>**Note**  In case you didn't create a second MDE with the layer `#CUSTOMER` you just have to add the following annotations in `ZRAPH_##_C_TravelWDTP` instead.

Please replace the current annotations of the field `TravelID` with the following annotations and activate it afterwards:
```abap
  ...
    @UI: { lineItem:       [ { position: 10,
                               importance: #HIGH,
                               label: 'Travel Identifier' },
                             { type: #FOR_ACTION, dataAction: 'acceptTravel', label: 'Accept Travel' } ],
           identification: [ { position: 10 },
                             { type: #FOR_ACTION, dataAction: 'acceptTravel', label: 'Accept Travel' } ],
           selectionField: [ { position: 10 } ] }
           TravelID;
  ...
```

The additional `#FOR_ACTION` annotations signal the Fiori Elements framework to show the action button in the application.
