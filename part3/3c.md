### Creation of Projection Views
[^ Top of page](#)  
The previously created Interface Views describe all available entities with their relations and elements of the business object hierarchy. In order to use them with a service, like in our case OData for Fiori User Interface (UI), we need a projection layer consisting of CDS Consumption Views which define the (possible subset of the) data model and functionality being available via this service. This UI service includes UI layout annotations, text elements, value helps and free-text search which will later be described in the OData service metadata.

Such UI layout annotations can be added in the CDS View directly above the fields in the selection list. As this can easily overload the CDS view and make it hard to read, it is a good practice to outsource those UI layout annotations into *Metadata Extensions (MDE)*.  

Additionally, this creates the possibility of one Interface View being used in several different OData services where requirements might differ requiring dedicated UI Annotations. Besides better readability this also allows several layers of metadata extensions: Existing CDS views with an MDE extension layer `#CORE` (e.g. standard implementation by SAP) can be reused with a second MDE in layer `#CUSTOMER` in which you only override those annotations not suited to your case without having to define others again. To enable this, we add the annotation `@Metadata.allowExtensions: true` to each CDS Consumption View.

In our scenario we’ll define the following four Projection Views (reading from the Interface Views with the prefix **C** indicating it being intended for service consumption via e.g. OData):

* ZRAPH_##_C_TravelWDTP 	
* ZRAPH_##_C_BookingWDTP
* ZRAPH_##_C_BookingSupplWDTP
* ZRAPH_##_C_RoomReservationWDTP

The relevant syntax is the following:
```abap
define [root] view entity <projection_view>
[provider contract transactional_query]
as projection on <projected_view>
```  

Now, let’s start with `ZRAPH_##_C_TravelWDTP` step by step. Create a new Data Definition with the before-mentioned syntax exposing all fields from `ZRAPH_##_I_TravelWDTP` while also exposing the Associations. Concerning associations: The composition of the child `ZRAPH_##_I_BookingWDTP` has to be redirected to (the not yet created) `ZRAPH_##_C_BookingWDTP` with the following syntax. The same has to be done for the second child `ZRAPH_##_C_RoomReservationWDTP`.  

```abap
_Booking : redirected to composition child ZRAPH_##_C_BookingWDTP
```  

You’ll find the final solution for our projection views further below as we’ll add the upcoming UI annotations step-by-step to the same structure of selected fields. The addition `provider contract transactional_query` is only necessary for the root view and can be omitted for childs.

### Defining Text Elements
[^ Top of page](#)  
To define a relationship between the elements `AgencyID`, `CustomerID` and their corresponding texts or descriptions, the text elements must be denormalized in the CDS projection view. Therefore, the elements of the associated text provider views (`_Agency.Name` and `_Customer.LastName`) are included in the selection list of the projection view. Their corresponding ID elements are annotated with `@ObjectModel.text.element: ['<field_name>']`.  

At runtime, the referenced element is read from the database and filtered by the logon language of the OData consumer automatically. Add this two text elements for the corresponding key field to your selection list. For detailed information, see: [Defining Text Elements](https://help.sap.com/viewer/fc4c71aa50014fd1b43721701471913d/201909.001/en-US/338fa3f46f284a9f9408f0481d36f497.html). 

### Defining Value Helps
[^ Top of page](#)  
Value helps are defined in the source code of the CDS projection view `ZRAPH_##_C_TravelWDTP` by adding the annotation `@Consumption.valueHelpDefinition: [{ entity : { name: '<CDS-view_name>', element: '<field_name>' } } ]` to the elements  `AgencyID`, `CustomerID` and `CurrencyCode`.  

In this annotation, you specify the elements for which the value help dialog should appear on the UI. The value help annotation allows you to reference the value help provider view without implementing an association. You simply assign a CDS entity as the value help provider and specify an element for the mapping in the annotation. All fields of the value help provider are displayed on the UI. When the end user chooses one of the entries of the value help provider, the value of the referenced element is transferred to the corresponding input field on the UI.  

You don’t have to explicitly define a CDS entity as value help provider but can reuse any existing one for the field in question. Add such value helps using the value help providers `/DMO/I_Agency`, `/DMO/I_Customer` and `I_Currency` for the corresponding fields of your selection list. You can check for the required field name by clicking `F2` while the value help provider is marked with your cursor. For detailed information, see: [Simple Value Help](https://help.sap.com/viewer/fc4c71aa50014fd1b43721701471913d/201909.001/en-US/9971cb3a97614009b078d2e5098296b7.html#loio9971cb3a97614009b078d2e5098296b7). 

>**Optional** If you like, you can also create a Value Help Provider CDS view by yourself – this is just a interface view providing the fields you want to filter and show in the value help. Also, you have the possibility to combine the search helps to only allow values for different fields in combinations which make sense. E.g. we could add a search help to our Booking CDS which only shows Connections for an already filtered Carrier. This uses the CDS keyword `additionalBinding` and can be easily implemented by providing the `localElement` name of the already filtered field together with its `element` name in the value help provider. For more information, see: [Value Help with Additional Binding](https://help.sap.com/viewer/fc4c71aa50014fd1b43721701471913d/201909.001/en-US/850b4ddd2526447db925bb54f18e2fdb.html).

### Defining Text & Fuzzy Search
[^ Top of page](#)  
In the projection view, you model the ability to search for specific values in the view. The entity annotation `@Search.searchable` is used in the travel projection to enable the general HANA search. This annotation also triggers the search bar in the Fiori elements UI. By using this annotation, you have to define elements that are primarily used as the search target for a free text search.  

These elements are annotated with `@Search.defaultSearchElement: true`. In addition, you can define a fuzziness threshold using `@Search.fuzzinessThreshold: 0.8` that defines how exact the search values must be in order to find element values. Add the last two annotations to the fields `AgencyID` and `CustomerID`. For more information on search, see [Enabling Text and Fuzzy Searches in SAP Fiori Apps](https://help.sap.com/viewer/fc4c71aa50014fd1b43721701471913d/201909.001/en-US/3ea081f47d6e4ce89391c6f982c82efa.html). 

### Creating the remaining three projection views
[^ Top of page](#)  
Now, `ZRAPH_##_C_TravelWDTP` is completed. But it cannot be activated as it’s redirecting the child associations to not yet existing CDS views. So we’ll create this second projection view exposing the fields and associations of `ZRAPH_##_I_BookingWDTP`.  

Don’t forget to redirect all composition associations. You can define text elements, value helps and search elements as you see fit (you can check the master data associations from the Interface View and decide what whout make sense to show in the app). This time, you'll need both child and parent associations like for `_Travel`:
```abap
_Travel : redirected to parent ZRAPH_##_C_TravelWDTP
```  
  
The same holds true for the `ZRAPH_##_I_BookingSupplWDTP`: Here we also have to create a projection view which redirects to its parent `ZRAPH_##_C_BookingWDTP` and the latter redirecting back to itself as child.  

Finally, create `ZRAPH_##_C_RoomReservationWDTP` also refering to its parent. When finished you can check the solutions for the whole chapter below and activate everything together at the same time.
